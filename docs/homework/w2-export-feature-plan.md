# 数据导出功能开发计划

## 1. 项目概述

### 1.1 目标
为 w2/db_query 数据库查询工具添加数据导出功能，支持 CSV 和 JSON 格式，实现一键查询并导出的自动化流程。

### 1.2 工期
预计 7 个工作日（1 周）

### 1.3 团队角色
- 后端开发：实现导出 API 和服务
- 前端开发：实现导出 UI 和交互
- 测试：编写单元测试和集成测试
- 文档：编写技术文档和用户手册

## 2. 开发阶段

### Phase 1: 后端基础功能（Day 1-2）

#### 任务 1.1: 创建导出服务模块
**负责人**: 后端开发
**工时**: 4 小时
**文件**: `backend/app/services/export_service.py`

**任务内容**:
- [ ] 创建 `ExportService` 类
- [ ] 实现 `export_to_csv()` 方法
  - 使用 Python `csv` 模块
  - 支持流式生成（Iterator）
  - 处理特殊字符转义
  - 处理 NULL 值
  - 空结果返回 0 字节文件
  - 非空文件使用 UTF-8 with BOM
- [ ] 实现 `export_to_json()` 方法
  - 使用 `json` 标准库
  - 包含元数据（rowCount, executionTimeMs, exportedAt）
  - 确保 JSON 格式正确
  - 空结果返回 0 字节文件
- [ ] 实现 `generate_filename()` 方法
  - 格式：`{database_name}_query_{timestamp}.{format}`
  - 时间戳格式：`YYYYMMDD_HHMMSS`

**验收标准**:
- 单元测试覆盖率 > 90%
- CSV 输出可被 Excel 正常打开
- JSON 输出符合规范格式
- 空结果导出符合 0 字节约定

**依赖**: 无

#### 任务 1.3: 实现导出 API 端点
**负责人**: 后端开发
**工时**: 3 小时
**文件**: `backend/app/api/v1/queries.py`

**任务内容**:
- [ ] 添加 `POST /api/v1/dbs/{name}/export/snapshot` 端点

- [ ] 校验结果快照结构（`columns/rows/rowCount`）
- [ ] 调用 `ExportService` 生成导出内容
- [ ] 返回 `StreamingResponse`
  - 设置正确的 `Content-Type`
  - 设置 `Content-Disposition` 头
- [ ] 错误处理
  - 404: 数据库不存在
  - 400: 请求参数或快照结构错误
  - 500: 导出序列化失败

**验收标准**:
- API 可通过 Postman/curl 测试
- 返回的文件可正常下载
- 错误响应格式正确

## 4. 风险管理

### 4.1 技术风险

| 风险 | 影响 | 概率 | 缓解措施 |
|-----|------|------|---------|
| 大数据集导出内存溢出 | 高 | 中 | 使用流式响应，限制最大行数 |
| CSV 特殊字符处理错误 | 中 | 中 | 使用标准 csv 模块，充分测试 |
| 浏览器兼容性问题 | 中 | 低 | 测试主流浏览器，使用标准 API |
| 查询超时 | 中 | 中 | 设置超时限制，显示友好提示 |

### 4.2 进度风险

| 风险 | 影响 | 概率 | 缓解措施 |
|-----|------|------|---------|
| 任务估时不准确 | 中 | 中 | 预留 20% 缓冲时间 |
| 依赖任务延期 | 高 | 低 | 关键路径优先，并行开发 |
| 测试发现重大 Bug | 高 | 低 | 早期集成测试，持续测试 |

## 5. 质量保证

### 5.1 代码质量标准
- 后端代码符合 PEP 8 规范
